GET continua funcionando (modo leitura degradada). É pré-condição transversal de **todos** os fluxos das §4–§9.

## 3. Ordem de execução (grafo de dependências)

```
A. Provisionamento ──► B. Autenticação e equipe
                          │
                          ├──► C. Cadastro (templates → Empresas → Responsáveis → overrides)
                          │        │
                          │        └──► E. Abrir Competência (fan-out)  ◄── exige ≥1 Empresa ativa
                          │                 │                               com template e contact.email
                          │                 ├──► F. Envio público (Link)
                          │                 │        └──► G. Conta do Responsável / minha-área
                          │                 ├──► H. Revisão / rejeição / desfazer
                          │                 │        └──► F2. Reenvio após rejeição (token rotacionado)
                          │                 ├──► I. Encerramento + ZIP
                          │                 └──► J. Mensageria, lembretes, crons
                          └──► D. Configurações e cobrança  (trava todo não-GET acima)
K. Segurança e isolamento transversais — rodar depois de A–J, com dois tenants
```

Regras duras de sequência:

- **E não roda** antes de C produzir Empresa `active`, com `checklist_template_id` e com `contact.email`.
- **F não roda** antes de E emitir o Link — o token só existe em claro no fan-out (capture na resposta do `POST /periods` ou no email do console).
- **H não roda** antes de F confirmar ao menos um documento (`upload_status = 'uploaded'`).
- **I (conteúdo do ZIP)** muda de significado conforme H tenha rodado ou não — teste as duas ordens.
- **F2** invalida o token usado em F; qualquer teste segurando o token antigo precisa buscar o novo.
